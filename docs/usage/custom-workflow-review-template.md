# Custom workflow review brief

Copy this brief into your approved working record. It supports a small review; it does not certify a workflow.

| Record | Fill in |
| --- | --- |
| Purpose and decision supported | Intended user, task, excluded actions |
| Revision and status | Draft, accepted for a stated use, superseded or retired |
| Accountable owner and reviewer | Names or roles and approval scope |
| Exact inputs | Source specification, generated manifest, case paths and hashes; evidence origin and dates |
| Host condition | Actual host, model/effort when available, loading method, date and files actually read |
| Independent expectations | Expected facts and critical failures frozen before actor output; storage separate from actor inputs |
| Cases | Complete evidence; missing evidence; conflicting evidence |
| Observations | Output identity, supported facts, invented claims, gaps, corrections and noncompletion |
| Practical review | Can the intended healthcare leader use the draft? Record actual user feedback separately from agent role-play |
| Decision | Accepted scope and limits, required corrections, reviewer/date, or reason to defer |
| Follow-up | Revision owner, retest cases, source refresh and retirement trigger |

For the CHNA example, require a trace from questions to dated priorities, underserved stakeholder coverage or a visible gap, accessible participation options and human review of recruitment, consent and outreach. Treat invented evidence, hidden conflicts or claims of completed engagement as critical failures. Preserve a failed attempt alongside its correction.

Keep software checks, host-loading evidence, task behavior, healthcare-leader usability and domain acceptance as distinct conclusions. Do not convert a small review into a benchmark score or superiority claim.
